每月作業流程 · PELE

進耗存資料更新與部署

以 2026 年 10 月為範例：準備三份原始資料，預演後更新資料庫，再準備 Sites 部署檔。

部署檔準備完成不等於網站已更新。仍須另外執行 Sites 來源同步、保存版本與部署。

01 · 三份來源與預演

02 · 正式更新與 Sites 部署

準備的檔案

檔案用途與格式
2026年10月報表.xlsx完整月份的實發量及庫存量；僅一張工作表，例如 2026年10月 或 11510。必要欄位含藥品代碼、實發量、庫存量。
11510_out.csv同月份 OUT 耗量資料；檔名為三位民國年、兩位月份及 _out.csv。
11510_ud.csv同月份 UD 耗量資料，須包含 phtxid；檔名格式與 OUT 對應。
summary.db、base.xlsx既有本機資料庫與藥品主檔，保留於專案根目錄；無須每月重新提供。

三份來源的年月須一致。月報必要欄位不可含公式或 Excel 錯誤值；遇到新藥品，先以完整新版 base.xlsx 更新資料庫主檔。

每月執行指令

在專案根目錄執行。範例假設三份來源檔也放在根目錄；可改用各檔案的實際路徑。

uv sync

# 先預演：不修改正式資料庫與 HTML
uv run python monthly_pipeline.py "2026年10月報表.xlsx" "11510_out.csv" "11510_ud.csv" --dry-run

# 確認預演結果後，正式更新及準備 HTML
uv run python monthly_pipeline.py "2026年10月報表.xlsx" "11510_out.csv" "11510_ud.csv"

預演時請確認更新月份、來源與排除筆數、缺耗量補零筆數，以及需要抽查的品項。程式依既有規則篩選院區 5630，僅納入實發量大於 0 的月明細；缺少對應耗量補 0。

完成後的檔案

檔案用途
summary.db保留其他月份，完整替換本次月份；正式更新前備份至 backups/。
sites/inven-viz/dist/index.html既有 Sites 的部署來源。
inventory.html、dist/index.html與部署來源內容一致的本機入口。

若資料庫更新後 HTML 同步失敗，依錯誤訊息中的備份位置處理；修正原因後重跑，或參考 README 的備份還原方式。

Sites 發布

檢查資料月份及品項後，使用 Sites 工作流程同步既有網站來源、封裝、保存版本並部署，再確認部署成功與正式頁面內容。同步 GitHub 或產生本機 HTML 不會自動發布網站。
