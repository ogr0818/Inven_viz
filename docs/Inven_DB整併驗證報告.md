# Inven_DB 整併驗證報告

驗證日期：2026-10-10。整併完成後，資料處理程式、資料結構文件與管理測試均位於 Inven_viz，執行時不需要 Inven_DB 資料夾或對應聊天。來源資料夾與對應專案由使用者手動封存，本次未刪除或封存它們。

## 單一入口

- `update_summary.py` 不帶參數即讀取專案內 `base.xlsx`、`月報表.xlsx`、`total_screen.xlsx`，更新既有 `summary.db`。DB 不存在時停止，不自動重新建立。
- 月資料常規單張工作表，也支援多張；依藥品代碼及年月合併，完整替換月報涵蓋的月份，保留其他歷史月份。
- `--replace-base` 只更新目前主檔，無須月報及耗量檔；保留穩定藥碼及歷史月明細。首次移機重建須明確指定 `--init`，不覆寫既有 DB。
- `--dry-run` 完成來源與資料庫驗證，但不修改檔案或建立備份。正式更新先備份，再於單次交易中寫入，失敗回復。
- 彙整在記憶體進行，不依賴或改寫 `summay.xlsx`。舊彙整 Excel 與 DB 管理介面仍可使用；網站產製及發布維持獨立步驟。

## 納入與修正

- 沿用本專案較新的 `manage_summary.py` 及兩份 ADR，保留空年月表清除舊月份、正實發量與歷史名稱／劑型規則。
- 抽出共用記憶體彙整與 DB 交易入口，避免不同操作複製出不同更新邏輯。
- 三份來源的必要欄位先拒絕公式及 Excel 錯誤。彙整與 DB 共用整數驗證，拒絕小數及 SQLite 整數範圍外數量，不四捨五入；合併使用可保留空值的整數型別，避免補零時經浮點數失真。
- 保留篩選前的月報藥碼、來源位置與筆數；即使實發量不大於零，也須匹配來源基本資料及 DB 目前主檔。
- 納入 `SCHEMA.md`、以目前模型產生的 `schema.sql`，以及來源 14 項管理整合測試；新增 12 項單一入口整合測試。
- README 說明固定路徑、單張／多張工作表、完整月份替換、主檔選項、預演、備份與移機方式。

## 實際驗證

56 項 Python 測試通過，涵蓋既有資料清理、Excel 彙整、網站產製、管理測試與單一入口。新增驗證包括非正實發量及空月份清除、多表年月配對、重複鍵、排除列未知藥碼、公式／錯誤／小數／超界、來源保護、預演、備份、主檔獨立更新，以及觸發器造成部分寫入失敗後的完整回復。

另將入口及其模組、三份真實 Excel、網站產製器與範本複製到獨立暫存資料夾；從另一個工作目錄執行，不複製既有 DB 或中間 Excel：

1. 明確首次建立成功，三張表排序後逐欄與現有 DB 完全相同：穩定藥碼 2,400、目前主檔 2,400、月明細 3,400 筆。
2. 月報共 3,467 筆，排除 67 筆非正實發量，57 筆缺耗量補零；結果為 579 個品項、115 年 01–09 月。
3. 預演未建立備份；正式更新與重跑均保持相同內容，更新前備份與更新前 DB 逐欄一致。
4. 使用重建 DB 產出的 HTML，與本專案既有 `inventory.html` 逐位元組一致。
5. 正式 `summary.db`、三份來源 Excel、`summay.xlsx`、`inventory.html` 的前後 SHA-256 均相同。本次未發布網站，也未重新執行瀏覽器驗證；HTML 一致性不代表新增執行過所有瀏覽器測試。

詳細結果及檔案指紋位於本機 `verification/inven-db-integration.json`。獨立驗證使用本專案既有 Python 環境；證明不依賴 Inven_DB 路徑，未宣稱在全新電腦重新安裝過依賴。
